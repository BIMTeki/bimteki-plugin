# BIMTeki 容積區域繪製（v2 / 新版 MCP）

幾何改由 `get_wall_centerline_outline` 供給：它每層回傳**已接好牆角（extend-to-intersection）、共角端點 snap 成同座標、門/無框開口處留空**的牆心線段 `segments: [[x1,y1,x2,y2],…]`（世界座標、公尺）。把這些線段直接串成封閉多邊形即為各區域邊界，**不要再手算中心線**。空間名稱與定位點則由 `get_building_plan_snapshot(elements=["texts"])` 取得。最後用 `create_bimteki_zones` 建立 Archicad Zone。

## 範圍界定

- **只處理「容積相關」區域**：主要空間（A1~I/H2/G3…）、陽台/挑空/外廊/騎樓/屋突、梯廳、安全梯/管道間/機電設備空間、停車空間/車道等。
- **不處理 site-level 區域**：建築面積、退縮地、保留地、鄰房侵占、騎樓地、各類綠化面積（這些由其他流程另行處理）。附錄對照表中索引 100~107、120~125 一律排除。
- **花台、露臺不繪製容積區域**：即使平面上有「花台」「露臺」文字標籤，一律略過不畫（露臺多為開放露天、不計容積；花台亦不計）。這兩者不要當成未辨識標籤反覆向使用者詢問，直接忽略。
- **一個文字標籤 → 一個 zone（無標籤空間併入最近的標籤）**。建築師通常會在每個要繪製的空間各放一個文字標籤。**若某容積相關空間沒有標籤，不要略過**：找出距離最近的空間標籤，將此無標籤空間**併入該最近標籤所屬的區域**。「最近」以無標籤空間的幾何中心到各候選標籤定位點的直線距離判定；若難以取捨，於摘要標「⚠ 請複核（無標籤空間併入推定）」由使用者裁定。**例外**：花台、露臺與 site-level 區域仍一律排除，不併入任何區域。

## 核心原則（務必遵守）

1. **計算完成後直接繪製**。算完 zone 陣列後立即呼叫 `create_bimteki_zones`，不需等待使用者確認。
2. **邊界一律取自 `get_wall_centerline_outline` 的 `segments`，不要手算、不要用猜的**。server 已把牆角接好、門處留空；你的工作是「串線段 → 描外周 → 橋接門開口」。**唯一例外是陽台外緣**（規則 B：需從 snapshot 取 thickness 後把中心線往室外偏移 thickness/2）。
3. **分類用權威對照**。文字標籤 → `lawName` 一律查本檔末尾〈附錄：LawName 對照表〉，並**一律傳整數索引**。**查不到對應索引時，一律填 `23`**。

## 開始前：自動讀取案型

**案型（共用 / 非共用梯廳）由 `get_project_core_snapshot` 自動決定，不要問使用者。**

### 0-A — 確認 BIMTeki 專案已開啟
呼叫 `check_connection` 確認連線，**再**呼叫 `get_project_core_snapshot`：
- 回傳成功（有 `building` 物件）→ 繼續 0-B。
- 回傳「no open project」或連線失敗 → 呼叫 `open_bimteki_project` 協助開啟 `.bteki`，成功後重抓 `get_project_core_snapshot`，確認取到 `building` 物件再繼續。

### 0-B — 讀取案型
從 `building.shared_hall` 判定：
- `shared_hall = true` → **共用梯廳**（規則 E：梯廳/管道間/樓梯間各自獨立成區）。
- `shared_hall = false` → **非共用梯廳**（規則 D：樓梯間等併入主空間）。
- 取得後告知使用者（例如「偵測到本專案為【共用梯廳】案型，將依規則 E 繪製梯廳區域。」），**不需**再請使用者確認或覆寫。

「要繪製哪些樓層」**不要**用文字直接問；先從 Archicad 取得樓層清單再列給使用者勾選（見 Step 0）。地下室、屋突層等一律以抓回來的清單為準。

## 工作流程

### Step 0 — 取得樓層清單，讓使用者勾選要繪製的樓層
**不要**用文字直接問「要畫哪幾層」。呼叫 `get_building_plan_snapshot(elements=["texts"])`，讀其頂層 `stories` 陣列（每筆有 `index / name / elevation / height`），把清單（以 `name` 為主、附 `index/elevation`，由低到高排序）列給使用者勾選（可複選或「全部」）。
- 帶 `elements=["texts"]` 可避免回傳過大；此回傳的 `texts` 之後也作為標籤來源（Step 3）。
- 以選定的樓層 `index` 作為後續 `get_wall_centerline_outline(stories=[...])` 與 floorInd 對應的依據。
- 若逾時或回 error 4001（樣板編輯器等 modal 開啟中），請使用者關閉 modal 後重試。

### Step 1 — 取得牆心輪廓線段（邊界幾何來源）
針對 **Step 0 選定的樓層** 呼叫 `get_wall_centerline_outline(stories=[...])`：
- 回傳每層 `{ index, name, segments: [[x1,y1,x2,y2],…] }`（世界座標、公尺）；segments 為**已接好牆角、共角端點 snap 成同座標**的牆心線段，**門/無框開口處留空、窗不留空（牆身連續）**。
- `gap_openings`：**用預設 `["door","casedOpening"]`**（門留空）。門開口的缺口正是判斷「同戶房間連通性」的線索（見 Step 4）。
- `wall_clean_tolerance`：預設 0.10（實際配對容差 = max(兩牆厚)/2 + 此值）。**若發現牆角沒接上、線段串不成封閉迴圈**，調大此值（如 0.2）重抓該層。
- 樓層多時建議逐層或少量分批抓。

### Step 1.5 — 取得空間標籤
標籤來源是 `texts`（每筆 `text / x / y / angle`）。若 Step 0 的 `get_building_plan_snapshot(elements=["texts"])` 已涵蓋選定樓層，直接沿用；否則針對選定樓層補抓一次 `get_building_plan_snapshot(elements=["texts"], stories=[...])`。
- 解析與過濾見 Step 3。

### Step 2 — 建立 floorInd 對應表
**不要**寫死「0=1F」。讀 `stories[].index / name / elevation`：
- `create_bimteki_zones` 的 `floorInd` 直接等於該樓層的 Archicad story `index`。
- 有地下室或 GL 層時地上層 index 會位移；以回傳 `index` 為準，並用 `name`（「地上一層」「地下一層」「屋突層」）對使用者標示確認。

### Step 2.5 — 取得圖層，讓使用者選擇放置圖層
- 呼叫 `get_project_layers` 取得圖層清單，列給使用者選擇（有「容積」「Zone」「檢討」字樣者優先提示）。
- 記住選定圖層（名稱與識別碼），於 Step 5 帶入每個 zone。
- 若 `get_project_layers` 無回應或尚未提供，**先告知使用者**並請其指定圖層名稱，不要逕自選一個。

### Step 3 — 辨識標籤、指派 lawName
`texts` 內含大量雜訊（材料說明、尺寸、剖面編號、施工註記），**必須**用末尾〈附錄〉的「排除清單」與「白名單」兩道過濾：先剔除材料/圖面註記字樣，再挑出真正空間標籤；位置相近（容差 ~0.3m）的重複標籤去重。
- 每個標籤 → 取 `lawName`（主要空間取前置碼 A1~I/H2/G3…；其餘如陽台、停車空間、梯廳、管道間以標籤文字直接對應）。**排除範圍外類別**（索引 100~107、120~125）。
- 標籤 `(x, y)` 為該空間定位點，於 Step 4 作為連通性 fill 的種子與區域歸屬依據。一個標籤對應一個 zone。

### Step 4 — 由線段串出每個區域的多邊形
幾何來源為 Step 1 的 `segments`。把線段串成封閉外周，**不要再手算中心線**。

**4-1 建鄰接、串迴圈**
- 把該層所有 `segments` 端點建鄰接（端點座標完全相同視為同節點；server 已 snap，通常可 exact match，必要時容差 ~1e-4 m）。
- 沿鄰接走訪可串出多個封閉迴圈（房間 faces）。門開口處留空形成「缺口」，是判斷連通性的線索。

**4-2 用標籤決定區域歸屬（門開口＝可通行）**
- 門開口缺口代表「可走通」：從某主空間標籤出發，**穿過門開口缺口、但不跨越任何實牆 segment** 所能到達的房間，視為同一戶 → 併成同一個主空間 zone（落實規則 C：整戶不挖空、內部隔間不收邊）。
- 不同戶之間或通往公共空間者，分界為一道**實牆**（無門開口或為共同壁），fill 不會穿過 → 自然分開。
- 各空間標籤同時作為 fill 種子：當一道含門的牆同時鄰接「住戶」與「梯廳」兩個不同標籤時，邊界落在**該牆中心線**上（兩區各自貼同一條中心線收邊），不要讓住戶 fill 漏進梯廳。

**4-3 描出區域「外周」多邊形（封口門開口）**
- 區域 `points` 取（已併好的）該區域**最外周**的中心線輪廓；內部隔間 segment 與內部門開口都在區域內，不納入外框、不挖空。
- **外周壓在含門的牆上時（入戶門、店鋪開口等）**：該處 outline 留空，但容積外緣應沿牆中心線連續通過 → **沿同一條牆線把缺口兩端共線的 segment 橋接起來**使外周閉合。可參考 snapshot 的 `wallEndGaps`（含 gap 與 collinear）判斷哪兩段共線。
- 橋接**只允許「同一條牆線、共線」的缺口**；不得跨越非共線的空白（那是真正的開放邊界）。

> ⚠ **每條邊都要落在某條 segment 上**（或為「沿同一牆線橋接的門開口」）。產生 points 後逐段檢查：若相鄰兩點之間「穿越空氣」（既非 segment、也非同線門開口橋接）→ 串錯或漏轉折，補齊。
> ⚠ **嚴禁截彎取直**：L 型缺角、退縮、陽台凹口務必沿每一段 segment 逐一列出轉折點，不可一條直線跨過缺角。
> ⚠ **嚴禁用軸線或外接框當邊界**：邊界一律取自 segment（陽台外緣除外）。不得拿橘色定位軸線(grid)座標或標籤外接矩形(bbox)代替——那會畫出懸空、不在牆裡的假邊界。
> ⚠ **某側串不起來**（segment 缺漏、牆角沒接上）：先把 `wall_clean_tolerance` 調大重抓該層；仍不行就在摘要標「⚠ 請複核（某側無對應線段，邊界待人工收邊）」，**不要硬拉直線封口**。

### Step 5 — 組出 zone 陣列（每筆）
- `points`（必填）：多邊形外框 `[[x,y],…]`，公尺、專案座標，至少 3 點，**免重複首尾**（系統自動封閉）。
- `name`（必填）：主要空間用完整標籤（「H2 住宅」「G3 店鋪」）；其餘用類別名。
- `lawName`（必填）：**一律傳整數索引**（查末尾〈附錄〉）。**查不到一律填 `23`**，不要改傳字串、不要留空。
- `floorInd`：填 Step 2 對應的 story index。
- `layer`：填 Step 2.5 選定的圖層。
- `height`：可省（預設 3.0）；要貼合樓高填 `stories[].height`。
- `number`：可省（自動流水號）。

### Step 6 — 直接繪製
立即呼叫 `create_bimteki_zones(zones=[...])`，不需等待確認：
- 一次批量上限約 **35~40 筆**；超過要分批。
- 回傳每筆 `guid / lawName / floorInd` 與失敗清單；失敗逐筆回報並說明可能原因。

### Step 7 — 完成摘要
依樓層分組給使用者：

| 樓層 | 區域名稱 | 請照空間(lawName) | 備註 |
|------|----------|-------------------|------|
| 1F (index 0) | H2 住宅 | H2 (23) | 主要空間，已併入衛浴/廁所/臥室/客廳（非共用案型含樓梯間） |
| 1F (index 0) | 停車空間 | 停車空間 (71) | |
| 2F (index 1) | 陽台 | 陽台 (35) | 外緣面＝欄杆中心線往外偏移 thickness/2 |
| 屋突 (index n) | 屋突層 | 屋突層 (34) | 整層單一區域，未細分 |

備註欄務必標出含不規則轉角／界線未閉合／陽台外緣／橋接門開口等需人工複核處。

## 分類規則 A~G

**A. 主要空間以牆中心線為界。** 直接用 outline 線段串外周。獨立柱亦同（柱中心）——柱需補抓 `get_building_plan_snapshot(elements=["columns"])` 取柱中心。

**B. 陽台：以矮牆/欄杆「外緣面」為界（非中心線）。** outline 只給中心線，故陽台需**補抓** `get_building_plan_snapshot(elements=["walls"], stories=[該層])` 取得該欄杆/矮牆的 `centerlineClean` 與 `thickness`，再把中心線**往室外**（離陽台標籤定位點較遠的方向）偏移 `thickness/2` 得外緣面。矮牆/欄杆判定：牆高 < 樓層 `height` 一半且通常 ≤ ~1.5m。此處只做「已知良好中心線 ＋ 往外 thickness/2」的單純偏移，**不碰 flipped / offsetFromOutside**。陽台邊界完全由牆幾何決定，不依賴樓板。

**C. 主要空間合併與命名。** 一戶＝**一個** zone，邊界取**整戶外牆中心線**的完整外周輪廓：廁所、衛浴、臥室、客廳、廚房、走道、戶內無獨立標籤的房間全部併入（不另計、不挖空、不在內部隔間牆收邊）；非共用案型下樓梯間亦併入（規則 D）。實作上：以 Step 4-2 的「穿門可達」連通性把同戶房間併起來。`lawName` 依用途填代碼（H2、G3…）；`name` 填完整空間名稱。

**D. 「非共用梯廳」案型：廁所、樓梯間、衛浴皆屬主空間；停車空間自成獨立 zone。**
- **停車空間**：無論案型一律獨立成區，lawName=71。
- **廁所、樓梯間、衛浴**：併入所屬主空間多邊形，不另計、不挖空、不獨立標 lawName。平面上的這些文字標籤視為主空間一部分。
- **主空間性質判讀不出來時**：找不到 A1~I 主要空間代碼且無法推斷用途，**一律以 H2（23）為預設**，name 填「H2 住宅」，並標「⚠ 請複核（主空間性質推定為 H2）」。

**E. 「共用梯廳」案型：梯廳、管道間、樓梯間分開繪製**，各自獨立成區並套對應 lawName（梯廳=41、管道間=59、室內安全梯=52、昇降機間=43…，視標籤而定）。

**F. 地下室：以地下室外牆中心線為界，每層一個區域**（不細分內部）。

**G. 屋突層：整層繪製為單一區域，不分內部空間。** 不論平面上幾個標籤（樓梯間、機房、水箱、露臺…）都**只畫一個** zone，涵蓋整層樓地板範圍：
- 邊界取該層**外牆中心線**串出的整體外周（比照 F「整層一區」，不挖空內部隔間）。
- `lawName` 一律填 **屋突層（34）**；`name` 填「屋突層」。
- 屋突層內露臺、花台仍依「範圍界定」略過（已含在整層外周內者不需特別處理）。
- 若屋突層僅有露臺/花台而無任何屋突構造物輪廓，向使用者確認是否仍需畫整層屋突區域。

## 對照表位置
LawName 對照表、文字標籤→lawName 解析規則、可辨識標籤白名單，**已內嵌於本檔末尾〈附錄：LawName 對照表〉**。填 lawName 前先讀該附錄。

## 已知地雷
- **主空間易畫太小（最常見錯誤）**：標籤通常只放在主廳，遠離標籤的房間易被漏掉。務必用 Step 4-2「穿門可達」把整戶房間併齊、沿整戶外牆中心線串出完整外周（規則 C）。
- **門開口連通性誤判**：門開口缺口讓 fill 可穿過。注意入戶門會通往公共空間——別讓住戶 fill 漏進梯廳（4-2）；描外周時入戶門要沿牆線橋接封口（4-3）。
- **線段串不成封閉迴圈**：牆角沒接上時，把 `get_wall_centerline_outline` 的 `wall_clean_tolerance` 調大（預設 0.10）重抓該層。
- **邊界線筆直又不落在牆中**：截彎取直／用軸線或外接框代替牆心線段的指紋。每條邊都要回扣到一條 segment（見 Step 4 ⚠ 區塊）。
- **陽台誤用中心線**：陽台要外緣面，需補抓 snapshot 取 thickness 後往外偏移 thickness/2（規則 B）。
- `get_project_autotext_catalog("volumeCheck")` 會逾時（modal），本流程用不到，別呼叫。
- 樣板編輯器為 modal，開啟時外部 MCP 呼叫回 error 4001 → 請使用者關閉後重試。

## 解析規則（文字標籤 → lawName）

1. **主要空間**：標籤前置碼為英文字母 A–I（後可接數字），例如 `H2住宅`、`G3店鋪`、`A1`。
   - 取前置碼 → 對應主要空間索引（下表 1~24）。
   - `name`（區域名稱）= 完整標籤文字（保留中文，例如「H2 住宅」）。
2. **其他類別**（陽台、停車空間、車道、梯廳、管道間、安全梯、退縮地、建築面積、屋突層…）：以標籤文字直接比對下表類別名稱 → 取索引。

4. 比對採「包含」原則並去除空白；同時命中多個時，主要空間代碼優先於通用字。
