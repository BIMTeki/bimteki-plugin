# BIMTeki 綠建築基準檢討表生成（基地綠化＋基地保水）

建築技術規則建築設計施工編第十七章「綠建築基準」依案件性質要求檢討五項：基地綠化、基地保水、建築物節約能源、建築物雨水及生活雜排水回收再利用、綠建材。本 skill 現階段做前兩項——兩者都是「面積 × 係數」型檢討，面積由使用者在 Archicad 繪製填充／區域，經外掛「自訂面積項目檢討」取得 autotext token，再依規範公式組表：

- **基地綠化**：合格判斷式 `TCO2 ＞ TCO2C`（綠化總固碳當量 vs 基準值）。規則、公式、係數表整理見 `references/greening-rules.md`。
- **基地保水**：合格判斷式 `λ ＞ λc`（基地保水指標 vs 基準值）。整理見 `references/water-retention-rules.md`。

> **範圍界定**：本 skill 檢討的是**建照審查用的技則第十七章基準**，不是綠建築標章（EEWH 分級評估）——後者另有九大指標與評定程序，不在範圍內。與土管綠化檢討（`bimteki-green-area-review-table`）也不同張表：一個案子可能兩張都要做。
>
> 需求前提：連上使用者本機 Archicad + BIMTeki Studio；訂閱含「自訂面積項目檢討」模組授權；MCP ≥ 0.12.0（要用區域組合）。

## 前置檢查

同 `../bimteki-custom-area-review-table/SKILL.md` 的前置檢查（連線與多開選定、版本關卡 MCP ≥ 0.12.0、`get_project_status` 的 finalized／hasFile 把關、`feature_not_licensed` 授權把關），不重抄。動手前告知使用者：將建立的檢討項目名稱、兩張樣板名稱——匯入區域與建表都會寫入專案並存檔。

## 第一步：讀專案資料，判斷檢討義務

呼叫 `bimteki:get_project_core_snapshot`（唯讀）取得判斷材料：

- `site`：基地面積（A0）、使用分區。
- `land`：法定建蔽率（r；多分區時的平均建蔽率）、地號合計。
- `building`：建築用途（判斷學校／農舍）、供公眾使用等。

再呼叫 `bimteki:get_project_custom_params`（唯讀）——若專案曾用 `bimteki-project-info-fill` 回填，可能已有地質調查、地下水位、山坡地等自訂參數可佐證免檢討判斷。

**免檢討判斷**（詳 references 兩檔第 1 節）：

| 情形 | 基地綠化 | 基地保水 |
|---|---|---|
| 基地面積 ≦ 300 m² | 免 | 免 |
| 個別興建農舍 | 免 | 免 |
| 本編第十三章山坡地建築（已依水保技規設計） | 要 | 免 |
| 地下水位 ＜ 1m（任一鑽孔） | 要 | 免 |

- 山坡地與地下水位 BIMTeki 通常讀不到——**問使用者，不要臆測**。
- 判定「免檢討」的項目：不建計算表；使用者需要時可建一張兩欄式「免檢討說明」小表（左欄條文依據 §298、右欄本案事實——面積類綁 autotext，如基地面積用 `面積：基地面積總計`），並在回報提醒「免檢討事由屬法規事實，請使用者複核」。
- 兩項都要檢討是常態；使用者只要做其中一項也可以，流程相同。

## 第二步：確認法規參數（需使用者確認，不可臆測）

| 參數 | 預設／判斷 | 要問使用者的情形 |
|---|---|---|
| β 固碳當量基準值 | 依使用分區：學校用地・公園用地 0.83／商業區・工業區（不含科學園區）0.50／其他 0.66 | 使用分區判讀不明確時 |
| r 法定建蔽率 | `land` 的法定建蔽率；**r＞0.85 以 0.85 計** | 分期分區局部評估（改用實際建蔽率）時 |
| α 生態綠化修正係數 | **預設 0.8**（全無生態綠化） | 使用者有生態綠化計畫才依 ra 計算（α=0.8+0.5×ra，須計畫書與計算表） |
| Ap 綠化困難面積 | 預設 0 | 有騎樓、私設通路、戶外運動設施等（見 greening-rules 清單）→ 請使用者繪製或提供 |
| f 最終入滲率 | **必問**：有鑽探資料→統一土壤分類查表；無→土質簡易判斷；回填土 10⁻⁵ | 一律要使用者確認，f 直接進公式 |
| λc 保水基準 | 0.5×(1−r)；**學校校園整體評估採 0.5** | 學校案要確認整體／局部評估 |
| 保水項目 | 預設只做常用 Q1～Q3 | Q4～Q8 特殊項目使用者指定採用才納入（含各自的深度／孔隙率／長度等參數） |
| t 降雨延時 | 86,400 秒（固定） | 不用問 |

## 第三步：規劃自訂面積項目結構

沿用 `bimteki-custom-area-review-table` 的原則：**一個檢討＝一個項目**，各組面積用「區域組合」（多顆合一顆合計 token）或散裝區域掛在項目下。本 skill 建**兩個項目**：

**項目「綠建築-基地綠化」**——每個實際採用的栽植類型一個組合（沒有的類型不建）：

| 組合名稱建議 | 對應 Gi | 使用者要畫的面積 |
|---|---|---|
| 生態複層 | 2.00 | 複層區樹冠總投影（樹心半徑 3.5m 範圍） |
| 闊葉大喬木 | 1.50 | 每株樹冠投影：間距≧基準→畫基準面積（一般基地 16m²/株、學校等 25、都會公園等 36）；間距不足→實際間距平方；老樹→實際樹冠投影；保留老樹→實際投影**畫二倍**（或公式×2 並註記） |
| 闊葉小喬木（含針葉、疏葉） | 1.00 | 同上 |
| 棕櫚類 | 0.66 | 同上 |
| 灌木 | 0.50 | 實際種植平面面積（每 m² 2 株以上） |
| 多年生蔓藤 | 0.40 | 實際立體攀附面積 |
| 草花草坪 | 0.30 | 實際種植平面面積 |
| 薄層壁掛綠化 | 0.30 | 薄層實際面積／壁掛立面投影面積 |
| Ap綠化困難面積 | — | 騎樓、私設通路等（Ap＞0 才建） |

**項目「綠建築-基地保水」**——依採用的保水項目建組合：

| 組合名稱建議 | 進入公式 | 使用者要畫的面積 |
|---|---|---|
| A1綠地被覆地草溝 | Q1 | **地下無人造構造物**的自然土地（下有地下室的花園不算 A1、歸 A3；下有地下室的裸露地完全不計） |
| A2透水鋪面 | Q2 | 透水鋪面範圍（基層厚 h 為常數另問，≦0.25m） |
| A3人工地盤花園 | Q3 | 人工地盤花園面積（V3＝A3×覆土深度，深度常數另問，≦0.6m） |
| A4貯集滲透空地 | Q4 | 可透水面積（V4 由深度常數換算），採用才建 |

Q5（側表面積）、Q6～Q8（長度、個數）不是平面面積，不建組合——由使用者提供數值當常數寫進公式，回報標明「此值非連動，設計變更需手改表」。

- 先 `bimteki:get_project_custom_area_review` 看現況（read-modify-write）；同名項目已存在時問使用者沿用或換名，不要重建。
- 面積來源用預設 `original`。
- **繪製約定**：建議使用者用**填充（Hatch）**逐類繪製並在 ID 標上組合名（例「闊葉大喬木」），一次選取全部後照名稱分組掛入（A 掛法）；沒標名稱就逐組選取（B 掛法）。掛區域的 actions 細節、`create_group` 不清散裝的坑、數量自檢，**全依 `bimteki-custom-area-review-table` 第二步**，不重抄。
- 樹冠投影填充的用途是把「株數×基準面積」轉成可連動的面積——使用者不願逐株畫時，退而求其次以「株數×Ai 基準」常數寫進公式（回報標明非連動）。

## 第四步：取 token

同 `bimteki-custom-area-review-table` 第三步：直接用 `get_project_custom_area_review` 回傳的 `groups[].token`／`zones[].token`，不經 catalog；token 綁 GUID、**項目結構定案後才建表**；先用 `bimteki:evaluate_autotext_values(category="customAreaReview")` 看數值。

另外兩顆專案層級 token（比對 catalog 取用，同建蔽率表）：

- A0 基地面積：`siteOverview` 分類 `面積：基地面積總計`（純數字，補「m²」）。
- r 法定建蔽率：`coverage` 分類 `比率：基準建蔽率`（渲染如 `60%`；**放進 `{=}` 公式會自動轉小數 0.6**，可直接寫 `1-{r}`）。

## 第五步：建表（兩張）

版式仿規範官方總表（結構見 references 各自最後一節），BIMTeki 多欄表；`{=...}` 公式規則同 `bimteki-custom-area-review-table` 第四步。**本表特有的公式眉角**：

1. **公式不能引用其他儲存格**——ΣGi×Ai、TCO2、ΣQi、λ 這些「彙總格」必須把所有 token 整條展開在同一格公式裡（segments 穿插 text 運算符與 autotext token）。
2. **公式引擎沒有 max/min／條件式**——規範有三處門檻：`A' ≧ 0.15×A0`、`Q ≦ Q0`、`r ≦ 0.85`。建表當下用 `evaluate_autotext_values` 的值判斷該用哪一支算式寫進表格，表上加註門檻條件文字（例「A'＝(A0−Ap)×(1−r)，低於 0.15×A0 時以 0.15×A0 計」），並在回報提醒：**模型面積大改可能翻越門檻，屆時檢討式要重建**。
3. 常數（Gi、β、f、t、α、h、覆土深度）為法規值或使用者提供值，以**純文字／公式常數**寫入並在回報標明來源；面積一律 autotext，不寫死。
4. 進位規範未明定，預設 `roundn(x, 2)`；λ 依慣例取 3 位（`roundn(x, 3)`）。
5. **多行儲存格的換行必須是真正的換行字元**：組 cells JSON 時寫 `\n`（單反斜線的 JSON 逸出）；寫成 `\\n` 會存進字面「\n」兩個字元，圖面上不會換行（2026-08-19 實測踩過，讀回驗證時檢查 `originaldata` 是否含字面 `\\n`）。

## 第六步：數值 sanity check 與回報

1. `evaluate_autotext_values(category="customAreaReview")` 取各組合面積，照 references 的公式手算 TCO2／TCO2C／λ／λc 一次，確認與表格公式邏輯一致（公式放置到圖面才會算出值）。references 兩檔末節各有一個官方計算案例可對照驗證公式寫法。
2. 回報內容：兩項檢討的義務判定依據（免檢討者說明事由）；採用的參數（β、r、α、f、λc）與其來源（分區判讀／使用者提供）；兩個檢討項目與其組合清單（名稱＋面積）；哪些量是常數非連動（株數估算、Q5～Q8、h、d、f）；三個門檻（A'≧0.15A0、Q≦Q0、r≦0.85）當下落在哪一側；提醒可在 BIMTeki 表格管理器放置到圖面，主選單「自訂面積項目檢討」可調整項目。

## 注意事項

- **與土管綠化表分清楚**：使用者說「綠化檢討」時先確認是土管綠化率（`bimteki-green-area-review-table`）還是綠建築固碳當量（本 skill）；「綠建築」「固碳」「保水」字眼才進本 skill。
- 免檢討判定（農舍、山坡地、地下水位）與 f 值屬法規／地質事實，讀不到一律問使用者；規範係數（Gi、β、公式）以 references 為準，**不要憑記憶改數字**；references 註明整理時之規範版本，發現與現行規範不符時以現行規範為準並回報。
- 覆土深度、樹穴面積、透水鋪面構造等**合格條件 BIMTeki 驗不到**——表上留人工勾選欄，回報提醒使用者自行檢核。
- token 綁 GUID：項目結構先定案再建表；刪項目／組合會讓已放置 autotext 變空字串（同 custom-area skill）。
- 匯入區域與建表會寫入專案並存檔；刪除既有項目或樣板須使用者明確同意。
