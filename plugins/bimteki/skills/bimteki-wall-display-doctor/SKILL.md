# BIMTeki 牆面表現診斷

協助使用者搞懂「我選的這道牆，為什麼長這樣 / 為什麼看不到」。先用 BIMTeki MCP 取得這道牆的設定與目前視圖環境，再依固定的判斷鏈，把表現成因（表面材質、填充、線、可見性）一層層拆給使用者看。

**bimteki 先行、Tapir 補足**：所有資訊優先用 BIMTeki MCP 工具取得；凡 bimteki 沒有提供的（最典型是「建材 → 表面材質」對應、牆的樓層連結/平面圖顯示細節），改用 Tapir（`archicad-mcp`）的工具補齊。

## 適用範圍

- **只診斷「牆」**。若選到的不是牆，`get_selected_element_settings` 只會回通用 `header`；此時告知使用者目前僅支援牆的深入診斷，並把 header 內容（type、圖層、樓層）列給對方參考即可，不要硬套下面的判斷鏈。
- **兩類問題**：
  - **表面材質**：為什麼是這個材質／顏色、跟我想的不一樣、跟隔壁牆不同 → 走〈判斷鏈 A〉。
  - **顯示**：為什麼看不到、為什麼填充/輪廓線/切割線長這樣、為什麼這層有/沒有這道牆 → 走〈判斷鏈 B〉。
- 使用者同時問兩類，就兩條鏈都跑。

## 核心原則（務必遵守）

1. **全程唯讀**。本 skill 只診斷、不修改。**絕不**呼叫任何會寫入模型的工具（`create_*` / `modify_*` / `delete_*` / `select_*`）。診斷不需要動到模型。
2. **bimteki 先行、Tapir 補足**。先用 BIMTeki MCP；缺的才用 Tapir 補。Tapir 未連線時，退而把已知資訊報給使用者，並明確指出「這部分需要你在牆設定/建材設定手動確認」。
3. **不臆測「目前套用哪一組圖形覆蓋」**。`get_current_view_settings` 拿得到專案內所有圖形覆蓋組合與規則，但**拿不到目前視圖實際套用哪一組**。一律比對「哪些規則會命中這道牆」，再請使用者確認目前套用組別，不要自己假設。
4. **表面材質三層優先級**：圖形覆蓋組合（最高，會蓋掉下面兩層）→ 牆設定的覆蓋表面 → 建築材料本身的表面。先有上層、上層就贏。

## 工作流程

### Step 0 — 取得選取元素
呼叫 `return_guid_of_selected_elements`。
- 回空陣列 → 請使用者先在 Archicad 中點選一道牆，再回來提問。
- 回多個 → **只診斷第一個**，並告知使用者；若對方其實想看別的，請其單選後重來。

### Step 1 — 取得這道牆的設定
呼叫 `get_selected_element_settings`，`guid` 帶入 Step 0 的第一個 GUID。確認 `header.typeName` 是牆。各區塊含義：
- `header`：guid、id、typeName、`floorInd`（始位樓層）、`layer`（圖層名稱 + hidden/locked）、`renovationStatus`（整修狀態）。
- `geometry`：起訖座標、厚度、高度、上下偏移、參考線位置與偏移、`flipped`。
- `structure`：結構型別（`basic` / `composite` / `profile`）與對應的**建材／複合結構／輪廓名稱**（注意：只給名稱，不給綁定的表面）。
- `lines`：切割線筆號/線型、未切割（輪廓）線型。
- `fills`：元素層級的切割填充筆號覆蓋（`null` = 沿用結構/建材設定）。
- `surfaces`：`reference` / `opposite` / `side` 三面表面材質（`null` = 沿用結構設定），與是否連動旗標。

### Step 2 — 取得目前視圖設定
呼叫 `get_current_view_settings`：
- `modelViewOptions`：螢幕視圖選項（門/窗顯示、填充真外觀或位圖、清潔牆樑交集等）。
- `layers`：`currentCombination`（目前生效的圖層組合名稱，無對應時為 `null`）＋ 全部圖層的 hidden/locked。
- `graphicOverrideCombinations`：專案內**所有**圖形覆蓋組合及其規則（含 `name`、`criterion` XML、覆蓋樣式 `style`）。
- `renovationFilter`：目前實際生效的整修篩選（guid 與 name）。

### Step 3 — 判斷問題類別，套對應判斷鏈
依使用者問的是「材質」還是「顯示」，跑〈判斷鏈 A〉或〈判斷鏈 B〉（或兩者）。

## 判斷鏈 A：表面材質（優先級由高到低）

逐面（外表面 / 內表面 / 邊緣）給結論。三面對應（依 Archicad 牆模型面板）：**`reference` = 外表面（參考線側）、`opposite` = 內表面、`side` = 邊緣**。

**A1 — 圖形覆蓋組合（最高優先）**
- 從 `graphicOverrideCombinations` 逐組逐規則，比對哪些規則的 `criterion` 會命中這道牆（常見條件：元素類型=牆、所在圖層、建材、id、翻新狀態等，逐條對照 Step 1 的 header/structure）。
- 命中、且該規則的 `style` 覆蓋了「表面」或「建材」→ 這是會蓋掉 A2/A3 的最高優先候選成因。
- ⚠ 因為拿不到「目前實際套用哪組」，措辭要用條件句：「**若**目前視圖套用的是〈X 組〉，其中規則〈Y〉會把表面蓋成〈Z〉」，並請使用者在**快速選項列**或**視圖設定**確認目前套用的覆蓋組合名稱。
- （可選佐證）若目前開啟的是具名 Navigator 視圖，可用 Tapir `GetViewSettings` 讀該視圖的 `graphicOverrideCombination` 名稱，幫使用者對照。

**A2 — 牆設定的覆蓋表面（模型面板）**
- 看 `surfaces`：某面**非 `null`** = 該面在牆設定被「覆蓋表面」開啟並指定了材質，直接讀該值。
- 若連動旗標為真 → 三面同一材質（改一面會連動）。
- 三面皆 `null` → 牆沒有覆蓋表面，往 A3。

**A3 — 建築材料本身的表面（`surfaces` 為 `null` 時生效）**
- 看 `structure` 的型別與名稱決定要查什麼：
  - `basic` → 單一建材。
  - `composite` → 各皮層各自的建材（外/內側皮層對應外/內表面）。
  - `profile` → 複雜截面輪廓。
- bimteki 只給建材/複合/輪廓**名稱**，**用 Tapir 補出實際表面**：
  - `GetAttributesByType(BuildingMaterial)` → 依名稱找到該建材，讀其綁定的表面（cut surface）索引或 attributeId。
  - 需要表面名稱時 → `GetAttributesByType(Surface)` 把索引/id 對到表面名稱。
  - `composite` → 先 `GetAttributesByType(Composite)` 取各皮層用的建材，再逐一查表面。
  - 實際回傳欄位名以該版本 Tapir 為準，取回後**檢查實際結構**再對應，不要硬套欄位名。
- Tapir 未連線/查不到 → 報出建材名稱，並請使用者到「建築材料」設定查看其綁定表面。

**A 的結論寫法**：實際顯示面的決定優先序為 A1（若命中且該組被套用）優先於 A2（該面有覆蓋），A2 再優先於 A3（建材表面）。逐面講清楚「現在是哪一層在決定」。

## 判斷鏈 B：顯示（B1~B4 交叉判斷）

「看不到」最常見成因是 B1 圖層與 B4 整修篩選；填充/線的長相多半是 B2。把四項綜合後，指出**最可能的主因**，其餘列為次因。

**B1 — 圖層可見性（最常見、最可靠）**
- `header.layer.hidden = true`，或 `get_current_view_settings.layers` 中對應圖層 hidden → **這就是看不到的直接原因**。
- `locked` 不影響「看得到與否」，但會讓牆無法被選取/修改——若使用者抱怨「選不到/改不動」，看這個。
- 一併把 `currentCombination` 名稱列給使用者對照（是哪個圖層組合把它關掉的）。

**B2 — 螢幕視圖選項 / 圖形覆蓋 對「線與填充」的影響**
- 切割線 = `lines.cut`（筆號/線型）；輪廓線 = `lines.uncut`；切割填充 = `fills`（`null` = 沿用建材的剖切填充）。
- 填充「真外觀 vs 位圖」、清潔牆樑交集等由 `modelViewOptions` 控制，會改變填充呈現方式。
- 圖形覆蓋也可蓋掉線型/筆號/填充 → 回扣〈A1〉比對到的命中規則（同一條規則可能同時改材質與線/填充）。

**B3 — 出現樓層範圍（始位 / 頂部連接 + 平面圖顯示）**
- `header.floorInd` = 始位樓層；`geometry` 的高度與上下偏移 → 判斷牆是否被「目前所在樓層的水平剖切面」切到（被切到才以**切割**樣式顯示，否則以**投影**樣式或不顯示）。
- 「平面圖顯示」（顯示在哪些樓層）與「頂部連接樓層」**若 bimteki 未回傳** → 用 Tapir `GetDetailsOfElements`（取牆的詳細參數）補；仍取不到 → 標「請於牆設定 →〈平面圖與剖面〉手動確認」。

**B4 — 整修狀態 vs 整修篩選**
- 比對 `header.renovationStatus` 與 `get_current_view_settings.renovationFilter`：若這道牆的整修狀態被目前篩選設為隱藏 → 看不到。這是「圖層明明開著卻還是看不到」的常見隱藏兇手。

## 輸出格式

先講**結論（為什麼）**，再附**依據**，最後列**待人工確認**。盡量精簡、結論導向。範例（表面材質）：

> **結論**：這道牆的外表面顯示為〈表面名稱〉，是由〈牆設定的覆蓋表面〉決定的（蓋過了建材原本的表面）。
> **依據**：
> - 圖形覆蓋（A1）：目前比對到〈規則X〉可能命中，但需確認套用組別（見下）。
> - 牆覆蓋表面（A2）：`reference` = 〈表面名稱〉、`opposite` = `null`、`side` = `null`。
> - 建材表面（A3）：建材〈建材名〉綁定表面為〈…〉（內表面/邊緣沿用此項）。
> **待確認**：目前視圖實際套用的圖形覆蓋組合（請在快速選項列查看），以決定 A1 是否真的生效。

顯示類問題比照辦理：先點出主因（例如「因為這道牆的圖層〈X〉在目前圖層組合〈Y〉中被關閉」），再列其餘 B 項佐證。

## 已知限制 / 地雷

- **拿不到「目前套用哪組圖形覆蓋」**：`get_current_view_settings` 只回所有組合與規則，不回目前生效組別 → 一律用條件句並請使用者確認，**不要**自己選一組當答案。
- **bimteki 無「建材→表面」查找**：必用 Tapir `GetAttributesByType`。Tapir 未連線 → 報建材名稱並請使用者於建材設定查看。
- **Tapir 回傳欄位名可能隨版本不同**：取回後先看實際結構再對應，不要硬套本檔寫的欄位名。
- **modal 卡住**：樣板編輯器等 modal 對話框開啟時，外部 MCP 呼叫可能逾時或回 error 4001 → 請使用者關閉 modal 後重試。
- **多選只診斷第一個**：要看別的請使用者單選後重來。
- **參數 key 必須與工具 schema 完全一致**，否則可能靜默退回預設值。
- 全程唯讀：再次提醒，**不呼叫** create/modify/delete/select 類工具。
