# 基地概要表 —— 逐列規格（標題 1 列 + 26 項固定列 + 退縮／扣除列 0~6 列 + 使用面積(建蔽率用) 0~1 列，列數依本案動態）

左欄標籤逐字照抄（不省略、不改寫）。右欄組法優先序：**複合算式 token（同時含公式與結果）＞ 多個數值 token 自組算式 ＞ 本案實際值純文字 ＞ 標準樣板句 ＞ 佔位符**。

比對前先 `get_project_autotext_catalog(category="siteOverview,buildingOverview,coverage,volumeCheck")`，以下表的 **display 名稱** 在回傳中比對取 `token`。**token 是各專案專屬的雜湊值，一律用 display 名稱比對後取用，絕不硬編碼下列任何 token 字串本身**——下列 `顯示名稱候選` 只是搜尋線索，實際專案的 catalog 回傳名稱可能略有出入，找不到就依規則退回下一優先序，不要臆測硬湊。

## Row 0：標題

- col 0：留空。
- col 1：「基地概要」，`textbold:true`、`textsize:1`、`alignment:2`（置中）、`newline:1`。

## 第一組：基本資料（Row 1~6）

### Row 1｜基地地號

- **顯示名稱候選**：`siteOverview` 分類中含「地號」字樣的項目（如「文字：地號」「地號（合併）」）。
- **找不到時**：檢查 `get_project_core_snapshot` 或使用者是否曾用 `project-info-fill` 寫入自訂義參數（可能以 `CustomParam.地號` 形式出現在 catalog，display 名稱通常就是使用者取的參數名）。
- **仍找不到**：佔位符 `◯◯◯段◯◯◯地號 等◯筆`。

### Row 2｜使用分區

- **顯示名稱**：`文字：使用分區`（siteOverview，已於其他表驗證過，優先綁）。

### Row 3｜起造人

- **顯示名稱候選**：`buildingOverview` 或專案資訊中含「起造人」「建築主」字樣的項目；或 `CustomParam.起造人`。
- **找不到時**：純文字帶入 `get_project_core_snapshot` 讀到的起造人/負責人欄位（如果有內建欄位）。
- **仍找不到**：佔位符 `◯◯◯建設有限公司 負責人：◯◯◯`。

### Row 4｜層棟戶數

- **需要的資料**：棟數（幢/棟的區分屬台灣建築常見用語，「幢」指共用逃生系統的建築群、「棟」指結構分棟，若專案只有一種棟數欄位，兩者可填同一數值並註明）、地上層數、地下層數、屋突層數、戶數。
- **顯示名稱候選**：`buildingOverview` 分類中「棟數」「地上層數」「地下層數」「屋突層數」「戶數」；`table-area-summary` 的案型判斷也用到 `block_count`（可作為棟數來源，透過 `get_project_core_snapshot` 的 `building.block_count.value`）。
- **組法**：多個數值 autotext 用文字串接，仿照範例格式：
  ```
  {幢數}幢、{棟數}棟、地上{地上層數}層、屋突{屋突層數}層、{戶數}戶
  ```
  找不到的個別欄位（例如本案無「幢」的概念）可省略該段，不要硬湊一個數字。

### Row 5｜基地面積

- **顯示名稱**：`siteOverview` 分類中「面積：基地面積」或「基地面積」。

### Row 6｜退縮／扣除相關列（**條件顯示、列數動態**）

**不是固定一列「道路退縮地」**，而是依本案實際有值的扣除項逐項插入，一項一列；面積為 0 的項目**不放**（不要留整列 0 的空扣除項）。與 `table-area-coverage` 的扣除列規則一致，兩張表的顯示項目應相同。

- **判斷資料來源**：`get_project_core_snapshot` 的 `land.areas`，或
  `evaluate_autotext_values(category="siteOverview")`；`abs(value) < 0.005` 視為 0。
- **候選項目與 display（依此順序排列，`siteOverview` 分類、path「基地概要/土地面積」，display 帶「總計」後綴）**：

  | 列標籤 | display | snapshot 欄位 |
  |---|---|---|
  | 保留地 | `面積：保留地面積總計` | `reserved_area` |
  | 道路退縮地 | `面積：道路退縮地面積總計` | `road_reserved_area` |
  | 道路退縮地(計入法空) | `面積：道路退縮地(計入法空)面積總計` | `road_reserved_empty_area` |
  | 鄰房侵占 | `面積：鄰房侵佔面積總計` | `neighbor_reserved_area` |
  | 騎樓 | `面積：騎樓面積總計` | `arcade_area` |
  | 騎樓地 | `面積：騎樓地面積總計` | `arcade_empty_area` |

  註：display 用的是「鄰房侵**佔**」（`佔` 非 `占`），比對時逐字對。
- **騎樓地列另有前提**：面積 > 0 **且** `review_settings.minus_arcade_from_site.value` 為真（面板「建蔽率計算時騎樓地從基地母數扣除」）才顯示；讀不到就問使用者，不要臆測。
- **值格寫法**：綁該項的 `面積：…總計` autotext。這類 token 放置後只渲染純數字、不帶單位 → 用
  `segments=[{autotext},{text "m²"}]` 補上 `m²`。
- **全部扣除項皆為 0 時**：本組列整組省略，Row 5 基地面積之後直接接「其它面積(使用面積)」。
- ⚠ **本組列數是動態的**：插入 N 列就把其後所有列（Row 7 起）的 row 索引整體 +（N−1）；下方「cells 對照速查」的 Row 編號是以「只有 1 列退縮地」為基準寫的，實作時一律以動態編號為準。

## 第二組：建蔽容積規定值 vs 設計值（Row 7~17）

### Row 7｜其它面積(使用面積)

- **顯示名稱**：`siteOverview` 分類（path「基地概要/土地面積」）的 **`計算式：使用面積總計計算式`**。這是**未扣除**騎樓、鄰房侵占等項目的使用面積（本案例渲染為 `93.00m²`）。
- ⚠ **不要跟下一列的「使用面積(建蔽率用)」搞混**：兩者 display 名稱只差「(建蔽率用)」五個字，但一個未扣除、一個已扣除，綁錯會讓後面的允建建築面積／法定空地面積對不起來。
- **找不到時**：退回 `面積：使用面積總計`（純數值，需補 `m²`）。

### Row 7-1｜使用面積(建蔽率用)（**條件顯示**）

把「基地面積扣掉各項扣除後＝建蔽率分母」的算式獨立成一列，讓圖面上看得到展開過程，而 Row 12 允建建築面積、Row 13 法定空地面積維持簡潔的 `77.28*60%=46.37m²` 形式（此排法與事務所既有基地諸元表一致）。

- **顯示條件**：本案**至少有一項扣除項面積 > 0**（即 Row 6 的退縮／扣除列有插入任何一列）。全部扣除項皆為 0 時本列省略——那種情況下它會渲染成與 Row 7 相同的數字，重複無意義。
- **顯示名稱**：`coverage` 分類的 **`計算式：使用面積(建蔽率用)總計計算式`**（複合算式 token），整格只綁這一個 token，不要補文字。
  - 本案例渲染：`93.00-1.38-14.34=77.28m²`
- **為什麼不自組**：這個 token 的減項是 BIMTeki 依專案實際扣除項產生的，日後多一項道路退縮地就會自動變成 `93.00-1.38-14.34-X=…`，與 Row 12／13 的結果永遠一致。**若改用多個數值 autotext 自組（如 `(基地面積－鄰房侵占－騎樓)`），減項會被寫死在樣板裡、不會跟著專案變動，式子與結果會脫節** → 不要這樣做。
- **左欄標籤**：`使用面積(建蔽率用)`。若使用者希望與事務所既有寫法一致、改成逐項列舉的 `使用面積-鄰房侵占-騎樓`，要提醒他扣除項變動時這個標籤需人工更新（token 本身仍會自動正確）。
- **找不到該 display 時**：本列省略，並在回報中說明；不要改用自組算式頂替。

### Row 8｜建蔽率（規定值）

- **顯示名稱**：`比率：基準建蔽率`（coverage，已於 `table-code-permit` 驗證過，優先綁）。
- 註：本列只放「規定值」，設計值在 Row 13「設計建蔽率」單獨列出，對照參考圖的欄位安排。

### Row 9｜容積率（規定值）

- **顯示名稱**：`比率：允建容積率`（volumeCheck，已驗證）。若本案沒有這個 token（無獎勵容積），退回 `比率：基準容積率`。
- 註：設計值在 Row 17「設計容積率」單獨列出。

### Row 10｜允建建築面積

- **顯示名稱候選**：優先找 `coverage` 中「算式：允建建築面積」這類複合 token；否則找單一數值「面積：允建建築面積」。
- **找不到任何 token**：自組算式：`{使用面積} × {比率：基準建蔽率} ＝ {結果或佔位符}`。

### Row 11｜法定空地面積

- **顯示名稱候選**：`coverage` 中「算式：法定空地面積」或「面積：法定空地面積」。
- **找不到**：自組 `{使用面積} × (1－{比率：基準建蔽率}) ＝ {結果或佔位符}`（1 減建蔽率的算式若無法用 segments 表示減法可簡化寫成文字「使用面積扣除允建建築面積」，操作數仍用 autotext）。

### Row 12｜設計建築面積

- **顯示名稱**：`coverage` 中「面積：設計建築面積」（本案實際設計的建築面積，即建蔽率計算的分子）。

### Row 13｜設計建蔽率

### Row 14｜總樓地板面積

## 第三組：工程造價（Row 18~20）

這三列的單價（元/m²）來自地方主管機關**每年公告**的工程造價標準（例如台中市每年發布的建築工程造價及施工費用標準），**BIMTeki 不會有這個 token**，屬外部行政公告資訊，不可臆測目前有效的單價數字。

### Row 18｜工程造價

- **樓地板面積操作數**：找 Row 14「總樓地板面積」或本案適用的計價面積 token 綁 autotext。
- **單價**：佔位符 `每平方公尺◯◯◯元（依當年度主管機關公告造價標準）`。
- **組法**：
  ```
  ({總樓地板面積} + {其他計價面積如有}) × 每平方公尺◯◯◯元（依當年度公告）＝ ◯◯◯元（請依公告單價計算後填入）
  ```
- 註：參考圖範例把陽台等未計容空間（41.85m²）併入計價面積，各地方規定不同，實際併入項目請使用者依當地工程造價標準表確認，不要照抄範例的係數。

### Row 19｜雜項工程造價

- **面積操作數**：雜項工程（如擋土牆、排水溝、庭院鋪面等）的面積基準因地方規定而異，若專案有對應 autotext（例如「面積：雜項工程面積」）就綁；找不到就佔位符 `◯◯◯m²（請依雜項工程項目認定）`。
- **單價**：佔位符 `每○○◯◯◯元（依當年度主管機關公告雜項工程造價標準）`。
- **組法**：`{雜項工程面積或佔位符} × 單價佔位符 ＝ ◯◯◯元（請依公告單價計算後填入）`。

### Row 20｜總工程造價

- **組法**：`{Row18結果} + {Row19結果} ＝ ◯◯◯元`；若 Row18/19 仍是佔位符，本列結果也維持佔位符，等使用者填完單價後才有意義，不要自己湊一個總數。

## 第四組：法規檢討（Row 21~27）

這 7 列是常見的「門檻判斷 → 標準結論」樣板句，**結論（免設置／應設置／OK）需依本案實際讀到的數值判斷後選擇對應分支**，autotext 只負責把數值即時帶入句子、不會自動做條件分支；數值接近門檻或用途特殊時，回報要提醒使用者複核。條文與地方自治條例可能因縣市而異，樣板句以下列（依台中市案例）為起手範本，不同縣市請使用者確認後調整。

### Row 21｜停車空間檢討

- **依據**：建築技術規則設計施工編第59條——建築基地位於都市計畫內區域，且总樓地板面積未達一定規模者，得免附建法定停車空間（門檻通常為 500m²，實際門檻與可扣除項目請對照使用執照所在地規定）。
- **需要的資料**：計價用樓地板面積（可能與 Row 14 略有不同，視法規對「總樓地板面積」的定義是否扣除陽台等）、實際設置車位數。
- **autotext**：樓地板面積、車位數盡量綁；門檻 500m² 為法規固定值，寫死為文字，不是佔位符。
- **樣板句（樓地板面積 < 門檻，免設但仍自行設置的情境）**：
  ```
  依建築技術規則設計施工編第59條，本案位於都市計畫內區域，且樓地板面積 {樓地板面積}<500m²，免設置停車位，自行設置 {車位數} 個停車位，符合規定，詳一層平面圖。
  ```
- **若樓地板面積 ≥ 500m²**：改為依標準需附建車位公式檢討，樣板句需使用者確認法定應設車位數如何計算（因用途組別而異），此情境無法直接套用免設句，回報時明確提醒。

### Row 22｜建築物污水處理設施

- **來源**：多為標準樣板句，視本案排水方式（接管排放 vs 現地處理設施）而定，BIMTeki 無強對應 autotext。
- **樣板句（設有現地處理設施）**：
  ```
  本案設置預鑄污水處理設施，詳（A6-○）污水處理設施詳圖。
  ```
- **若本案接管至污水下水道系統**：改為「本案污水接管至污水下水道系統，免設置現地污水處理設施」，由使用者依實情選擇。圖號留佔位符。

### Row 23｜無障礙建築物檢討

- **依據**：建築技術規則設計施工編第167條第1項第1款（連棟住宅型建築的無障礙通路規定）與無障礙設施設計規範202.4（建築基地未達10個住宅單位者，得免設置室外通路）。
- **需要的資料**：戶數（住宅單位數）。
- **autotext**：戶數綁 Row 4 用過的同一個戶數 token。
- **門檻**：10 個住宅單位。
- **樣板句（戶數 < 10）**：
  ```
  依建築技術規則設計施工編第167條第1項第1款，本案屬連棟建築物，該棟自地面層至最上層均屬同一住宅單位且第二層以上僅供住宅使用，地面層仍應設置無障礙通路。但依建築物無障礙設施設計規範202.4，免設置：建築基地未達10個住宅單位者，得免設置室外通路。本基地 {戶數} 戶住宅單位，免設置，符合規定。
  ```
- **若戶數 ≥ 10 或非連棟純住宅**：不適用免設句，本表僅能提示，需要完整檢討請改用 `table-code-accessibility`（該 skill 涵蓋第167條系列全部條文，回報時可建議使用者接著跑該 skill 做完整版）。

### Row 24｜衛生設備檢討

- **依據**：建築技術規則設備編第37條，住宅每一居住單位應設衛生設備數量規定。
- **來源**：標準樣板句，通常指向各層平面圖佐證，不強求 autotext。
- **樣板句**：
  ```
  依建築技術規則設備編第37條住宅檢討，依規定每一居住單位一個，詳各層平面圖。
  ```

### Row 25｜地質鑽探檢討
